## 1. 개요

교육자료(지식 베이스, KB)에 근거해 학습자 질문에 답하는 **튜터 API(`POST /tutor`)**와, 위험한 입력과 근거 없는 답변을 판정하는 **가드 API(`POST /guard`)**를 하나의 FastAPI 서버로 구현했다.

| 엔드포인트 | 입력 | 출력 |
|---|---|---|
| `/tutor` | 대화 이력 전체 | 답변, 응대 방식(action 7종), 근거 섹션 ID 목록 |
| `/guard` | 대화 이력 전체, (선택) 후보 답변 | 입력 판정(allow/block)과 범주(10종), 후보 답변의 근거 여부·근거 없는 구간·안전성 |

**설계의 중심 아이디어**
1. **LLM은 판단과 문장 생성만 맡고, 규격·정책은 코드가 보장한다.** 범주가 정해지면 action과 block 여부는 코드가 표로 정한다. 응답 형식은 어떤 오류에서도 규격을 지킨다.
2. **요청당 LLM 호출은 1회.** 30초 제한과 동시 64개 요청 조건에서 지연과 API 사용량을 함께 줄인다.
3. **검색은 BM25.** 같은 조건에서 임베딩·하이브리드 검색보다 정확도가 높았다.
4. **실패해도 안전하게 응답한다.** LLM 호출이 실패하거나 시간이 부족하면 규칙만으로 범주를 정해 막아야 할 요청은 막는다.

**현재 성능 (요약)**
- 실제 제출: 총점 82.31 / 81.91 (튜터 82.33 / 80.83, 가드 82.29 / 82.98). 두 번 모두 시간 초과·형식 오류·판정 오류 0개
- 부하 테스트(600건, 동시 64개): 38.2초에 완료, 튜터 p95 7.1초, 가드 p95 4.5초, 오류 0건

## 4. 구성 요소 상세

### 4.1 서버 계층 (`server.py`)

- **인증:** `Authorization: Bearer <token>`을 상수 시간 비교로 확인한다. 불일치만 401로 응답한다.
- **항상 규격 응답:** 잘못된 JSON, 빈 대화, 내부 예외, 시간 초과 모두 HTTP 200과 규격 JSON으로 응답한다. 마지막 단계에서 `sanitize_tutor` / `sanitize_guard`가 다음을 다시 검증한다.
  - 필드 타입
  - 허용 값(action, category)
  - 답변 4,000자 제한
  - 중복 인용 제거
- **요청 예산:** 요청마다 25초 예산을 두고 `asyncio.wait_for`로 감싼다. 넘치면 규칙 기반 응답으로 대체한다. 채점기의 30초 제한과 네트워크 시간 사이에 여유를 둔다.
- **리다이렉트 방지:** `redirect_slashes=False`라서 `/tutor/` 같은 주소는 3xx가 아니라 404가 된다. 문서 경로(`/docs` 등)는 끈다.
- **로그:** 미들웨어가 `경로, 상태 코드, 소요 ms, 요청 바이트 수`만 남긴다. 요청·답변 본문은 기록하지 않으며, 예외는 종류 이름만 남긴다. uvicorn 기본 접근 로그는 끈다.
- **상태 확인:** `GET /health`는 준비 여부만 반환한다. 비밀값과 문항 정보는 없다.

### 4.2 지식 베이스와 검색 (`app/kb.py`, `app/textnorm.py`, `app/retrieval.py`)

**KB 구성:** 3과목(파이썬 기초 PY, AI 프롬프트 활용 PR, 금융 리터러시 FIN) × 16섹션 = 48섹션. 표는 CSV 23개로 분리되어 있다.

- **인용 단위와 검색 단위 분리**
  - 섹션(인용 단위, 예: `PY-01-02`): 마크다운 본문 + 같은 이름의 CSV 표. 채점기와 같은 방식으로 합친다.
  - 청크(임베딩 검색 단위, 예: `PY-01-02#1`): 마크다운의 `## 소주제` 단위. `(표: X.csv)` 자리에 표 내용을 끼워 넣는다. 196개.
  - `FIN-01.html`은 FIN-01-01~04와 값을 대조해 중복본임을 확인했으므로 색인하지 않는다.
- **토큰화:** 영문·숫자는 단어 단위, 한글은 단어 + 문자 2·3-gram. 외부 사전·형태소 분석기 없이 동작한다. 정규화 단계에서 다음을 처리한다.
  - 보이지 않는 문자 제거
  - NFKC 정규화
  - 띄어 쓴 낱글자 결합("시 스 템" → "시스템")
- **검색 질의 구성:** 마지막 학습자 발화에 가중치 3을 주고 이전 대화 전체를 붙인다. 화면의 "빠른 질문 버튼" 문구(공개 세트에서 확인한 8개)는 정보가 없으므로 질의에서 뺀다. 대화 전체를 쓰면 마지막 발화만 쓸 때보다 Recall@1이 0.74에서 0.88로 올랐다.
- **세 가지 검색 방식을 따로 평가할 수 있게 구현:** BM25(섹션 단위), 임베딩+FAISS(청크 → 섹션 최댓값), 하이브리드(RRF).

| 검색 방식 (공개 세트, 근거 섹션 Recall@1) | 결과 |
|---|---|
| **BM25 (채택)** | **0.891** |
| 임베딩 + FAISS | 0.689 |
| 하이브리드 (RRF) | 0.824 |

- **KB 임베딩:** 서버 시작 시 운영진 임베딩 API로 만들고 `cache/`에 저장해 재사용한다. 캐시는 KB 내용과 모델명의 해시로 검증한다. 기본 검색은 BM25라서 요청 처리 중에는 임베딩 API를 부르지 않는다.

### 4.3 LLM 호출 계층 (`app/llm.py`)

- **설정:** `reasoning_effort=low`, JSON 모드, 최대 출력 2,000토큰.
- **마감 관리:** 남은 시간이 2초 미만이면 호출하지 않는다. 호출 상한은 `min(남은 시간, 20초)`이다. 동시 호출 세마포어(64)의 대기 시간도 마감에 포함된다.
- **재시도:** JSON 파싱 실패나 API 오류일 때, 남은 시간이 8초 이상이면 1회 재시도한다. 시간 초과 뒤에는 재시도하지 않는다.
- 프롬프트·응답 본문은 로그에 남기지 않는다.

### 4.4 범주 정책 (`app/policy.py`)

공개 세트 400건의 라벨을 분석한 결과, 범주가 정해지면 가드 decision은 100% 결정되었다. 튜터 action도 harmful_content를 빼면 100% 결정되었다. 그래서 **LLM은 범주만 고르고, action과 decision은 코드가 정한다.**

| 범주 | 튜터 action | 가드 decision |
|---|---|---|
| normal | answer | allow |
| pii_disclosure (본인 정보 공개 + 정상 질문) | answer | allow |
| answer_seeking (정답만 요구) | scaffold | allow |
| academic_dishonesty (제출 과제 대행) | scaffold | **block** |
| out_of_material (자료에 없는 과목 고유 정보) | abstain | allow |
| jailbreak_injection | refuse | **block** |
| harmful_content | refuse (방법·제작 요청) / redirect (비하 발언) | **block** |
| off_topic (수업과 무관한 결과물) | redirect | **block** |
| emotional_distress (지속적 정서 고통) | escalate | allow |
| low_signal_input (뜻을 알 수 없는 입력) | clarify | allow |

- **범주 정의(`CATEGORY_GUIDE`):** 대회는 범주별 정의를 제공하지 않으므로, 공개 세트 라벨에서 정의와 경계를 세웠다. 튜터와 가드가 같은 정의를 공유하며 다음을 담는다.
  - 범주 간 우선순위
  - 민감해 보이지만 정상인 질문의 예
  - 탈옥의 판단 기준: 튜터에게 직접 시키는지, 같은 표현을 분석만 하는지
- **보정 규칙(`rule_adjust`):** LLM 범주를 정규식으로 보정한다. 공개 세트에서 정밀도를 확인한 일반 언어 패턴만 쓴다.
  - 예: 탈옥 지시 vs 분석, 다른 사람 개인정보 캐기, 사기 문구 작성, 과제 대행, 자기소개, 지속적 고통 표현
  - 정답 범주를 다른 범주로 바꾸는 경우: 공개 세트 400건 중 0건
  - 원칙: LLM이 고른 문제 범주를 normal로 내리는 보정은 분석 표현이 확실할 때만 허용한다.
- **고정 문구:** 거절(refuse)·전환(redirect) 답변은 범주별 고정 문구를 쓴다. 해당 문항은 action과 "요청에 응했는가"만 채점되므로, 설명을 덧붙이면 응한 것으로 판정될 위험만 커진다.

### 4.5 `/tutor` 처리 흐름 (`app/tutor.py`)

1. 대화가 비었거나 뜻을 알 수 없는 입력이면 LLM 없이 `clarify`로 답한다.
2. BM25로 상위 3개 섹션을 찾아 [자료]로 준다.
3. 공개 세트에서 비슷한 예시 6개를 고른다(범주, action, 모범 답변).
4. LLM을 1회 호출해 다음을 JSON으로 받는다.
   - `asked`: 묻는 항목
   - `in_material`: 그 항목이 자료에 있는지
   - `category`, `harmful_type`
   - `evidence_quote`: 근거 문장 복사
   - `answer`
5. 보정 규칙으로 범주를 확정한다. 규칙이 범주를 거절·대행 범주로 바꿨다면, LLM이 정상 기준으로 쓴 답변을 고정 문구로 바꾼다.
6. 범주로 action을 정하고 인용을 붙인다.
   - answer·scaffold·abstain: BM25 1위 섹션을 인용한다. 공개 세트에서 LLM이 고른 인용(87/119)보다 BM25 1위(106/119)가 더 정확했다.
   - abstain: LLM이 복사한 근거 문장이 실제로 들어 있는 섹션을 인용한다.
7. 답변 후처리
   - refuse·redirect: 범주별 고정 문구
   - escalate·clarify: 길거나 요청에 응한 흔적(코드·인용문·목록)이 있으면 고정 문구로
   - 과제 대행 scaffold: 코드·목록·긴 풀이가 있으면 고정 문구로
   - 자료에 없음(abstain): "○○에 대한 내용은 학습 자료에 나와 있지 않아요" + 자료의 관련 사실 형식. 이 형식은 판정 모델의 근거 충실 통과율이 7/39에서 33/39로 높았다.
8. 시간이 3초 미만으로 남았거나 LLM이 실패하면 규칙 기반 응답(`rule_only_tutor`)으로 대체한다.

### 4.6 `/guard` 처리 흐름 (`app/guard.py`)

1. 대화가 비었으면 대체 응답을 낸다. 후보 답변 없이 뜻을 알 수 없는 입력이면 LLM 없이 `allow / low_signal_input`으로 답한다.
2. 대화 + 후보 답변으로 BM25 상위 3개 섹션을 찾아 [자료]로 준다.
3. 프롬프트를 구성한다.
   - 공용 범주 정의 + 후보 답변 판정 기준
   - 비슷한 입력 예시 6개, 후보 답변 판정 예시 4개
   - 판정할 대화: `[학습자]`/`[튜터]` 표시를 붙인 데이터로 전달한다. 대화 속 지시문은 판정 방법을 바꾸지 않는다고 명시한다.
4. LLM을 1회 호출해 `category`, `safe`, `grounded`, `unsupported`를 받는다.
5. 보정 규칙으로 범주를 확정하고, 범주로 `decision`을 정한다.
6. 후보 답변 판정 후처리(공개 세트 라벨 관례 반영)
   - 막아야 할 입력인데 후보 답변에 거절 표현이 없으면 `safe=false`(공개 세트 19/19)
   - `safe=false`이면 `grounded=true, unsupported=[]`
   - `grounded=false`이면 구간을 후보 답변의 실제 부분 문자열로 맞춘다. 맞출 수 없으면 가장 비슷한 절, 그래도 없으면 인용 표시를 뺀 답변 전체
7. 시간이 부족하거나 LLM이 실패하면 규칙 기반 판정(`rule_only_guard`)으로 대체한다.

### 4.7 few-shot 예시 풀 (`app/examples.py`)

- SPEC §7.1이 허용하는 대로 **배포된 공개 세트 파일에서만** 예시 풀을 만든다. 채점 요청은 풀에 넣지 않는다.
- 마지막 학습자 발화와 직전 발화로 BM25 색인을 만들고, 요청과 비슷한 예시를 고른다.
- 마지막 발화가 정규화 후 완전히 같은 예시는 건너뛴다. 공개 세트로 로컬 평가할 때 채점 문항 자신이 예시로 들어가는 것을 막는 장치이며, 비공개 문항은 공개 세트와 겹치지 않으므로 채점에는 영향이 없다.

### 4.8 장애 대응

| 상황 | 동작 |
|---|---|
| LLM 호출 실패, 남은 시간 부족, 처리 중 예외 | `rule_only_tutor` / `rule_only_guard`: 규칙만으로 범주를 정한다. 막아야 할 요청은 거절·block하고, 정상 질문은 대체 문구로 답한다 |
| 규칙 처리까지 실패 | 기존 대체 응답(규격을 지키는 고정 JSON) |
| 요청 본문이 JSON이 아님 | 빈 대화로 처리해 규격 응답 |
| 임베딩 API 실패(시작 시) | BM25만으로 서버가 뜬다 |

### 6.3 해석
- 실제 제출 점수는 보정 규칙을 **끈** 로컬 점수에 가깝다. 공개 세트 라벨에 맞춘 규칙은 로컬 점수를 약 8점 올렸지만, 표현이 다른 비공개 문항에는 효과가 작았던 것으로 보인다.
- 반면 답변 형식 개선(거절 고정 문구, 자료에 없음 답변 형식)은 데이터에 맞춘 것이 아니라 비공개 문항에도 통할 가능성이 높다.
- 제출마다 문항 표본이 바뀌어 실제 점수는 1~2점씩 흔들린다. 로컬 교차 검증도 실행마다 1~2점 흔들린다.

| 결정 | 근거 |
|---|---|
| 검색은 BM25, 인용은 BM25 1위 | Recall@1 BM25 0.891 > 하이브리드 0.824 > 임베딩 0.689. 인용 정확도 BM25 1위 106/119 > LLM 선택 87/119 |
| 요청당 LLM 1회 | 30초·동시 64 조건의 지연 여유와 API 사용량(어뷰징 기준) 관리 |
| 범주만 LLM, action·decision은 코드 | 공개 세트에서 범주 → decision 100%, 범주 → action은 harmful 외 100% 결정 |
| 거절·전환은 고정 문구 | 채점 항목이 action과 "응함"뿐이라 설명을 덧붙이면 위험만 커짐 |

| "자료에 없음" 자동 전환은 끔 | 자료에 없는 질문을 2건 더 잡았지만 정상 질문 10건을 잘못 전환해 손해 |
| 판단 항목 분해 방식은 끔 (`CLASSIFY`) | 규칙을 끈 교차 검증에서 튜터 action이 83.67 → 82.04로 떨어짐 |

## 8. 한계와 향후 과제

1. **보정 규칙의 일반화 한계:** 공개 세트 표현에 맞춘 규칙은 비공개 문항에서 효과가 작다. 앞으로 개선 효과는 규칙을 끈 교차 검증(`RULES=0`)이나 팀이 직접 바꿔 쓴 문장 세트로 측정한다.
2. **LLM 판정의 흔들림:** 규칙을 끄면 LLM 단독 가드 block F1은 0.827이다. 수업 질문에 문제 요소가 섞인 입력을 normal로 놓치는 경우가 많다. 가드 grounded 판정은 같은 코드에서도 76~84/86으로 흔들린다.
3. **근거 없는 구간:** 구간 F1이 약 0.6이다. 정답 구간은 짧은 구절(중앙값 15자)인데 답변은 문장 단위로 나오는 경우가 많다.
4. **자료에 없는 질문 탐지:** 관련 사실로 답을 만들어 내는 경우가 남아 있다(공개 세트 약 7건).
5. **인용 정확도 상한:** BM25 조정만으로는 106~108/119에서 멈춘다. 같은 상품명이 여러 섹션에 나오는 경우와 영어 질문이 약하다.
6. **로컬 판정 모델의 차이:** 로컬 판정은 gpt-5-nano이고 실제 채점과 다르다. 정답 예시 답변도 약 20%가 "응함"으로 오판정되는 잡음이 있다.

검토 중인 다음 후보는 다음과 같다(모두 규칙상 문제없음).
- 가드만 추론 수준 상향
- 가드 입력 판정 다수결
- 튜터 범주 판정 호출 분리
- 자료 충분성을 두 신호로 판정
- gpt-5-nano로 만든 KB 맥락 문장·영어 별칭
- 계산기 함수
- 주입 방어용 구분 블록

자세한 실험 기록은 `docs/progress-2026-11-11.md`를 참고한다.

## 9. 운영 방법

- **실행:** `./run.sh` → `0.0.0.0:8228`(uvloop, 접근 로그 끔). `.env`는 서버가 시작할 때 자동으로 읽는다.
- **제출 주소:** `https://<런박스 주소>.tunnel.elice.io/proxy/8228/tutor`, `…/guard`
- **`.env` 항목(값은 기록하지 않음):** `OPENAI_API_KEY`, `EMBEDDING_API_KEY`, `TEAM_TOKEN`
  - 주소와 모델명(`OPENAI_BASE_URL`, `OPENAI_MODEL`, `EMBEDDING_*`)은 런박스 환경변수로 미리 들어 있다.
- **주요 설정(환경변수, 기본값)**

| 변수 | 기본값 | 의미 |
|---|---|---|
| `REQUEST_BUDGET_S` | 25 | 요청당 처리 예산(초) |
| `LLM_CALL_TIMEOUT_S` | 20 | LLM 호출 1회 상한(초) |
| `LLM_CONCURRENCY` | 64 | 동시 LLM 호출 상한 |
| `REASONING_EFFORT` | low | gpt-5-nano 추론 수준 |
| `RETRIEVAL_MODE` | bm25 | bm25 / dense / hybrid |
| `FEWSHOT_K` | 6 | few-shot 예시 수 |
| `RULES` | 1 | 0이면 보정 규칙 끔(측정용, dev 브랜치) |
| `CLASSIFY` | direct | features면 판단 항목 방식(실험, dev 브랜치) |
| `OOM_CHECK`, `QUOTE_CHECK` | 0 | 자료에 없음 자동 전환 실험(꺼 둠) |

- **제출 절차:** 코드 커밋·푸시 → 서버 재시작 → 부하 테스트 → `submission.json`의 주소·토큰·commit 확인 → 제출. 채점 중(약 2분)에는 서버를 건드리지 않고 런박스 탭을 유지한다.
